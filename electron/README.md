# v2rayN · Electron shell (experimental)

This folder hosts a lightweight Electron front-end that reads the existing `guiNConfig.json` file and `guiNDB.db` SQLite catalog generated by the .NET (WPF/Avalonia) clients. The goal is to give front-end developers a familiar stack without rewriting the ServiceLib core logic.

## Getting started

```bash
cd electron
npm install
npm run dev
```

- `npm run dev` launches Electron with `electronmon` so the window reloads when you edit the renderer or main process code.
- `npm start` runs vanilla Electron without file watching (useful for smoke testing production-like builds).

## Pointing to an existing dataset

By default the shell tries the following locations (in order):

1. A custom path stored in `~/.config/v2rayn-electron.json` (created the first time you launch the app)
2. `V2RAYN_DATA_DIR` environment variable (if set)
3. A `v2rayn-data` folder inside the repo (either `electron/v2rayn-data` or a sibling next to the `electron` folder)
4. Electron's `app.getPath('userData')/v2rayN`
5. `$HOME/.config/v2rayN`

You can also use the **Change Data Folder** button inside the UI to point to any folder that already contains `guiConfigs/guiNConfig.json` and `guiConfigs/guiNDB.db`. The choice is persisted across sessions.

## What works today

- Renders the list of server profiles from SQLite (`ProfileItem` table) with subscription labels
- Reads and updates the current default server stored in `guiNConfig.json`
- Provides quick feedback/toast notifications for common actions
- Includes a small preference store + sensible defaults when `guiNConfig.json` does not exist yet
